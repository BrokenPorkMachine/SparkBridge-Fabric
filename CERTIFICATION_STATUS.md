This is expected. rc3 improves the integrity and portability of certification evidence; it does not manufacture the missing real-platform evidence required for 1.0.

Note on what `source.audit` does and does not prove: the audit suite asserts invariants against exact source text and cannot detect a compilation failure. Whenever `cargo` is unavailable on the generating runner, the evidence log now records `NOT VERIFIED: cargo was not available on this runner` so a `source.audit` PASS is never mistaken for a clean build. Native build evidence comes only from the per-platform `rust.*` checks, which stay skipped — and therefore blocking — until run on the named platform.

## rc3 evidence guarantees

- all merged bundles must identify the same source revision;
- every required PASS must carry evidence;
- referenced evidence files are copied into a portable bundle;
- every copied evidence file is checked by SHA-256 and byte size;
- assembled bundles include an evidence manifest;
- release/protocol/schema/source identity blockers are reported;
- required performance-threshold blockers are reported;
- blocker triage includes a recommended next action;
- CI aggregation and the DGX self-hosted lane use the same portable evidence workflow;
- generated certification outputs do not alter the fallback source revision.
