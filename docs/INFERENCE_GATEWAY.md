# DGX Inference Gateway

## Purpose

The gateway is the only remote inference surface in SparkBridge v0.3. Ollama stays on localhost. The gateway adds TLS, authentication, admission control, streaming behavior, residency control and timing evidence without rewriting Ollama's model semantics.

## Authentication

All `/api/v1/inference/*` routes require:

```text
Authorization: Bearer <gateway-token>
```

The gateway token is generated by `sparkbridge pki init` or `sparkbridge gateway-token rotate`. Remote clients also trust `ca.pem` so the DGX server certificate is verified.

## Chat

```bash
curl --cacert ./ca.pem \
  -H "Authorization: Bearer $SPARKBRIDGE_GATEWAY_TOKEN" \
  -H 'Content-Type: application/json' \
  https://dgx-spark.example.lan:7790/api/v1/inference/chat \
  -d '{
    "model":"qwen3-coder:30b",
    "messages":[{"role":"user","content":"Explain this compiler error"}]
  }'
```

The gateway forces `stream:true`. Tool definitions and other Ollama chat fields are preserved because the request body is forwarded as JSON rather than narrowed into a SparkBridge-specific chat schema.

## Generate

`POST /api/v1/inference/generate` behaves the same way and forwards to Ollama `/api/generate`.

## Residency

Load/retain:

```json
{
  "model": "qwen3-coder:30b",
  "action": "load",
  "keep_alive": "2h"
}
```

Unload:

```json
{
  "model": "qwen3-coder:30b",
  "action": "unload"
}
```

SparkBridge uses Ollama's documented empty-generate request to load/unload the model.

## Cancellation

The response header contains `X-SparkBridge-Request-ID`. Deleting that request signals the streaming task to stop; dropping the upstream reqwest body propagates cancellation to Ollama.

```bash
curl --cacert ./ca.pem \
  -X DELETE \
  -H "Authorization: Bearer $SPARKBRIDGE_GATEWAY_TOKEN" \
  https://dgx-spark.example.lan:7790/api/v1/inference/requests/<id>
```

Client disconnects are also detected through stream drop cleanup so scheduler capacity is returned.

## Admission

`inference_max_concurrent_requests` bounds active streams. Waiting requests are bounded by `inference_queue_timeout_seconds`; SparkBridge returns `503` instead of creating an unbounded queue.

For large DGX Spark coding models the initial recommended setting is one active request. Later agent scheduling can multiplex logical agents deliberately rather than relying on uncontrolled HTTP concurrency.

## Streaming

The gateway sends:

```text
Content-Type: application/x-ndjson
Cache-Control: no-cache, no-transform
X-Accel-Buffering: no
```

Do not place a buffering reverse proxy in front of the gateway unless buffering is explicitly disabled.

## Metrics

Ollama's final NDJSON event is parsed for its nanosecond timing values while the original bytes are forwarded unchanged. SparkBridge adds gateway-side timings:

- queue delay;
- provider connection/header setup;
- time to first streamed chunk;
- whole gateway wall time.

No prompts or generated source text are stored in the v0.3 telemetry snapshot.

## Security boundary

The gateway's upstream `ollama_base_url` must be loopback HTTP. SparkBridge configuration validation rejects arbitrary LAN/Internet Ollama endpoints in this release. This prevents the gateway from accidentally becoming a credentialed proxy to another machine.

The v0.3 gateway uses one appliance bearer token rather than per-human principals. Principals/ACLs remain a later policy iteration.
